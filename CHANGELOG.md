# Changelog

## v0.3.1 — 2026-10-27

Generate working test cases up front, so healing is rarely needed. On the warehouse API a clean run without
healing reached 118/119 cases without test defects (99%, up from 95%), with planner corrections down from 223
to 47 and no dropped cases.

### Added
- **Observed data** (`Observation`, `SRG_OBSERVE`): read-only GET samples of the SUT taken before planning, shown to
  the planner and the recipe designer as values/format context (never as expected statuses).
- **Workflow recipes:** the recipe designer reads the requirements and adds composite setups (e.g. a product plus a
  customer allowed to see and afford it); up to 6 recipes.
- **Planner rule statistics:** `srg plan` lists the most frequently broken validation rules; the failure analysis
  prints the share of cases without test defects.
- IR rules: a step that sends no body although the endpoint has required fields is rejected; a 2xx state change must
  not use an entity looked up from shared data.
- **Status sets:** `expected_status: "401|403"` when the specs allow several statuses for one condition (every one
  must be documented); compiled to the native Bruno assertion `res.status in [401, 403]`.

### Fixed
- Recipes were unusable in modules without the actor their steps run as (e.g. `admin` creating a customer for a
  customer-only module): such cases failed validation and the planner fell back to shared catalogue data. Modules now
  get the actors their recipes need.
- Fixtures backed by an environment variable that is not set are no longer offered to the planner (they sent empty
  ids: `ENV_FAILURE`); the analyzer uses env fixtures only for secrets. Re-analysis removes stale fixtures from Gel.
- The lesson extractor states the scope its evidence shows and prefers tolerant instructions over claims about the
  API (a single heal had produced "manufacturers are always lowercase").
- Observed samples are trimmed to contract-guaranteed fields, so optional ones (`requestId`, `pagination`) do not
  invite assertions.

### Changed
- `srg reset` keeps lessons (`--knowledge` deletes them too).
- Planner prompt: free-text values the API may normalise are compared case-insensitively unless the contract
  documents the format; undefined behaviour (case sensitivity of enum values, tie order) is not asserted; computed
  values come from the case's own data.

## v0.3.0 — 2026-10-27

Fewer broken generated test cases. On the warehouse API, a fresh run went from 103/212 to 142/157 passing,
with no `TEST_DEFECT` or `ENV_FAILURE` left.

### Added
- **Deterministic Bruno compiler** (`engines/bruno/compiler.py`): requests, auth, variables, extracts and checks
  translate one-to-one. Each check is a `test()` with a readable message (`expected == "PAID", got "DRAFT"`).
  The LLM synthesizer is only a fallback; `srg build` takes seconds.
- **Contract facts:** `ApiEndpoint.required_body_fields`, `assertable_paths` (guaranteed response fields per status)
  and `requires_auth`. Prompts list them literally, and the planner sees the full contracts of other modules'
  endpoints used for setup.
- **Setup recipes** (`SetupRecipe`, `srg recipes`): reusable setups designed by the LLM once per analysis, run once
  against the API, and offered to the planner and healer only when verified. A `type: recipe` step is expanded into
  ordinary steps before storage. `SRG_RECIPES=false` skips them.
- **Lessons** (`Lesson`, `srg lessons`): verified heals are generalised into short rules that are added to future
  planner and healer prompts.
- **Login actors from the spec:** documented test accounts log in once per run (collection script); no tokens in `.env`.
- `srg heal --lint` repairs cases that violate the current rules (with verification); `srg heal` also picks up
  cases stuck in `NEEDS_REVIEW` and skips failures that were already healed.
- Pre-flight service check before pipeline commands; `restart: unless-stopped` for Gel and MinIO.

### Changed
- **IR validation** rejects, so the planner or healer fixes them before storage:
  - requests expected to succeed that miss contract-required fields;
  - assertions/extracts on optional or undocumented response fields, and object keys on list paths;
  - `$env` references that no actor or fixture declares;
  - fixed values for unique fields (username, email) in creating requests;
  - modifying pre-existing (seed) entities instead of ones the case created;
  - list filters on paginated endpoints without the maximum page size.
- New list-filter path syntax: `response.body.data[model='X'].id`.
- **Guard rails against healing toward bugs:**
  - a 2xx for a request missing contract-required fields is diagnosed as `APPLICATION_BUG` by rule;
  - the healer must keep such negative steps;
  - lessons may not call contract-required fields optional.
- Response schema checks are generated by code (`validate_schema`), not written by the LLM.
- A deterministic normalizer repairs common Bruno mistakes (query params, auth vs explicit `Authorization`
  header, quoted regexes).
- Diagnostics reject placeholder answers; only 401s are grouped across actors; `--max-llm` is honoured.

### Schema (applied automatically by `srg doctor`)
- New: `SetupRecipe`, `Lesson`, `RecipeStatus`.
- New fields: `ApiEndpoint.requires_auth`, `required_body_fields`, `assertable_paths`.

## v0.2.0 — 2026-10-26

### Added
- **Failure analysis:** `srg diagnose`, and automatically after `srg test`.
  - A rule pre-classifier handles environment failures without an LLM call.
  - A ReAct diagnostics agent investigates the rest, with tools for the HTTP exchange, the OpenAPI contract, the requirements, the test files, the case history and a one-time rerun.
  - Categories: `APPLICATION_BUG`, `SPEC_MISMATCH`, `TEST_DEFECT`, `ENV_FAILURE`, `FLAKY`, `UNKNOWN`. Each result is stored as a `DiagnosticNote`.
  - Failures with the same signature are grouped and investigated once; `--max-llm` caps the investigations.
- **Self-healing:** `srg heal`, or `srg test --heal`.
  - `TEST_DEFECT` cases are repaired by the LLM, within guard rails: same type, requirements and endpoints; documented status codes only; the case must actually change.
  - The repaired case is rebuilt and verified in a `HEAL_VERIFY` run, then kept (`READY`, tagged `healed`) or rolled back (`NEEDS_REVIEW`).
  - Every attempt is audited as a `HealAttempt`.
- **Swagger 2.0 support:** body/formData parameters, `#/definitions`, `basePath`, `host`/`schemes`. Non-API YAML/JSON files in a spec folder are reported as skipped.
- **Dashboard:** diagnoses on the run page and heal history on the case page; the chatbot knows about diagnoses.
- **LLM usage summary** after every command.

### Changed
- **Faster LLM pipeline** (about 6× faster `srg build`):
  - each conversation has its own OpenCode session;
  - thinking is off for the synthesizer (`SRG_THINKING`);
  - default concurrency is 8;
  - prompts use compact JSON.
- **More robust LLM calls:**
  - automatic, sticky prompted-output fallback;
  - chunked planning (`SRG_PLAN_CHUNK_SIZE`);
  - a failing planner chunk no longer aborts `srg plan`.
- **Bruno validation:** upper-case response header keys (`res.headers['X-Request-ID']`) are now rejected.
- **Runner:** assertion and test failures are read from bru's per-result details.

### Schema (applied automatically by `srg doctor`)
- New: `DiagnosticNote`, `HealAttempt`, `DiagnosticCategory`, `DiagnosticSource`, `HealStatus`.
- New field: `TestRun.kind` (`SUITE` / `HEAL_VERIFY`).
